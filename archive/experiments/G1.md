## 预注册判据（S1-SDC.md §5，先于实现写定）

1. sic 的 pooled lost ≤ 0.7 × select 的 pooled lost
2. ≥ 3 个 context（行）
3. 配对 McNemar 显著（p < 0.05）

## 设计

每个行（context）独立建一个 19 块的 append-only 窗口（E6a 路径，无压缩无驱逐），
探针集只收"金答案在被选择丢弃的块里"的问题（约束 4，防饱和），eligible =
full-pool 对且 no-memory 错（E6a `recovery_report` 定义原样复用）。

五个臂在同一窗口、同一探针集上比较：

| 臂 | 选择规则 |
|---|---|
| select | 原生 `_select_block_indices`（importance 0.4 + recency 0.3 + goal + diversity） |
| sic | 30 探针梯度累积的 `block_salience` top-9 |
| oldest | 丢最老保最新（recency 极端化对照） |
| random | 随机 9 块（种子固定） |

sic 的梯度来自 S0 反传路径的改造：池叶子 `requires_grad`，每探针一次
gold-CE 反传取窗口切片 [32, 4864, 4096]，逐块 Frobenius 范数平方累加。
读模型全冻结，梯度检查点开启（S0 教训：eval() 会静默跳过检查点分支）。

## 结果（4 行，76 eligible 探针）

| 臂 | pooled lost |
|---|---|
| select | **19** |
| sic | **9** |
| oldest | 18 |
| random | 16 |

- 逐行：row0 3→3，row1 9→3，row2 4→1，row3 3→2（sic 四行无一更差）
- 判据 1：9 ≤ 0.7×19 = 13.3 ✓（实际比值 **0.474**，lost 降 52.6%）
- 判据 2：4 个 context ✓
- 判据 3：McNemar 配对 b=13（select 独丢）/ c=3（sic 独丢），连续性校正
  χ²=5.062，**p = 0.0245** ✓；配对自洽 b−c = 10 = 19−9

## 结构性发现（比判据本身更重要）

**sic 系统性保留最老的块 [0,1,2,3]，select 系统性丢弃它们。** 四行的
kept 重叠仅 4–5/9；sic 独有的块集中在窗口头部（0–5），select 独有的集中
在中段（10–15）。梯度信号说：探针要的函数信息在最老的块里，而原生打分器
的 recency 权重（0.3）把它们让给了中段的近似重复块。这与 G0 直接互证——
相似度无法区分版本（G0：同主体新旧块余弦 0.975），所以 recency-led 的
原生选择在版本语义下拿新弃旧，但 Conflict_Resolution 的金答案在新块，
探针的支撑事实却可能因相似度塌缩落在老块。显著性选择不需要区分版本：
它直接问"哪块承载探针要的函数"。

对照臂佐证：oldest（保最新）lost 18 ≈ select 19，recency 方向的丢失是
结构性的；random 16 也不差——说明 select 相对随机几乎没有增益，"丢一半"
本身就是主要损伤，而 sic 是唯一把损伤砍半的信号。

## 度量协议备注

- recovered 全为 0：本设计里 recovered 需要合并臂（sicm）才有意义，
  G1 是纯选择比较，recovered 列只是协议占位。
- sicm 臂（零空间投影合并 + 回滚门）在本次运行未启用（`--arm sic`），
  它是 G3 探针翻转率的前置；算子已实现并通过 GPU 验证
  （正交保证 max|⟨g,ΔB⟩| ≈ 8e-7，fp16 基 12.6 MB/块·层）。
- 单行 eligible 15–22，四行合计 76；p=0.0245 在该 n 下已过 0.05 线，
  但距离 0.01 有余量，G2 扩行数后需复核。

## 与证据链的关系

- G0（版本盲）：相似度分不开新旧 → 原生选择的信号天生缺失版本信息。
- **G1（本实验）：用探针梯度补上这个缺口，lost 19→9，p=0.0245。**
- E6（行为塌缩）：压缩丢掉正确版本 → 行为掉点的机制链闭合。
- 下一步 G2：版本分层验证（被 sic 救回的探针是否集中在"老块含金答案
  前身"的情形）；G3：sicm 翻转率 + 回滚触发统计。
