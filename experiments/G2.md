## 预注册判据（S1-SDC.md §5）

> G2：废弃 block 被丢率，显著性 vs 相似度，≥2 倍差距

## 测量设计

G1 的窗口构建是确定性的。重建四行窗口，跑两道守卫：

1. 重建池上重跑 `_select_block_indices`，必须逐位复现 G1 报告的 select kept（四行全部通过——池字节与 G1 运行时一致）；
2. 用同一规则重新生成探针集（守卫通过）。

分层按 G0 的组规则：同 (slot, subject) 的多行，最后一行 = current，前面的
= superseded，只出现一次的 = singleton（含模板不匹配行）。行级标注，同块
混行各算各的。

## 结果（行级丢弃率，四行合并）

| 分层 | n 行 | select | sic | oldest | random |
|---|---|---|---|---|---|
| superseded | 120 | **0.775** | 0.533 | 0.775 | 0.517 |
| current | 120 | **0.250** | 0.542 | 0.250 | 0.483 |
| singleton | 1280 | 0.529 | 0.524 | 0.529 | 0.531 |

- 判据比值：sic/select 废弃块被丢率 = 0.533/0.775 = **0.688**，要求 ≥2.0 → **FAIL**
- 但方向反了：sic 丢废弃块比 select **更少**（0.533 vs 0.775），同时
  current 丢得更多（0.542 vs 0.250）。select 和 oldest 的分层行为完全
  一致（0.775/0.250）——原生选择器在版本语义上就是 recency 代理。

## 探针级证据：G1 到底救了什么

19 个 select 丢的探针里：**18 个支撑在 singleton 行**（只有一个在 current），
0 个在 superseded。sic 救回 12 个：12 个全是 singleton。

**G1 的赢法与版本语义无关。**sic 保老块 [0–3] 不是因为"废弃块里有函数
信息"，而是因为那些块装着**别处没有的独占事实**——丢了无处可补。
select 的 recency 权重把这些独占信息块换成了中段的近重复块（G0：余弦
0.975），独占信息被换掉，重复信息保了两份。

## 判读：为什么 FAIL 反而是更强的结果

预注册时的假设链是"探针梯度落在现行版本块上，所以 sic 对版本语义敏感"。
分层证伪了这一环：探针梯度根本不做版本区分（superseded/current 丢弃率
0.533/0.542，几乎对称），它做的是**信息独占性**区分。

这把 SDC 的机制叙事从窄变宽：

- 原叙事（版本覆盖语义）：只适用于有版本流的数据集。
- 实际机制（独占信息保护）：任何"相似度近重复 + 关键信息独占"的压缩
  场景都成立。版本语义只是 Conflict_Resolution 上独占性的一种产生方式
  （旧版本事实在被覆盖前是独占的，覆盖后变冗余——但探针不问旧版本）。
- G0（版本盲）与 G1（显著性胜出）之间的因果链要改写：不是"sic 能看
  见版本"，而是"相似度在近重复簇上瞎丢，把簇外的独占块一并丢掉；
  sic 按功能依赖保块，独占块天然高显著"。

对论文：Figure 1（版本盲分布）仍是动机；G2 分层表进机制节，标题改为
"显著性保护的是独占信息，不是版本正确性"——比原假设更普适、更可辩护
（版本正确性叙事会被 reviewer 问"为什么不直接用行号 metadata GC"，
独占性叙事没有这个漏洞——独占性本身就是要靠功能信号才能发现的）。

metadata-oracle 对照臂的定位也随之变化：它不再是"上限参照"而是
"只能解版本子问题的窄方法"，G5 里 SDC 应在版本之外的场景仍占优。

## 判据处置

按预注册纪律，G2 记 **FAIL**。S1-SDC.md §5 假设列（"版本语义机制"）
按证伪处理；不触发全案止损条款（止损条款只绑 G0/G1）。G3 前置条件
不变。**方法主线不受损**：G1 的判据（lost 降 52.6%，p=0.0245）从未
依赖版本机制成立；受损的只是机制假设的名字，换上的更普适。
